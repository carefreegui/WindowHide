## P0 · 先修"会让人以为工具坏了"的

### ✅ P0-1 无响应目标(已完成)

**事故**:隐藏一个卡死的全屏游戏,工具界面直接"未响应",只能强杀;游戏也回不来。

已做:
- 隐藏/恢复整体移入工作线程(`_submit`),主线程只发信号、画界面
- 动手前用 `IsHungAppWindow` 判定,hung 就完全不动
- 所有能异步的调用都异步化(`ShowWindowAsync` / `SWP_ASYNCWINDOWPOS`)
- **慢窗口缓存**:取标题耗时 ≥40ms 就把 hwnd 记 30 秒,期间一次 IPC 都不发。
  实测"首次 172ms → 之后 45ms"(3 个挂起窗口曾把刷新从 31ms 拉到 349ms)
- 界面上这类窗口标题显示 `(无响应)`,不再是一片空白
- 忙时不丢请求而是**排队**(以前点"恢复"可能被直接丢弃 = 毫无反应)
- 隐藏成败判定改成等异步落地(`wait_offscreen`),不再把成功误报成失败

### ✅ P0-1b 强制隐藏全屏游戏:默认关闭

实测永劫无间被最小化后主线程死掉,游戏回不来。所以「先最小化再隐藏」降级为
设置项、默认关闭;默认行为是"藏不掉就如实报告"。

### ✅ P0-2 日志无限增长(已完成)

`log.py` 1MB 轮转、留 3 份。`logic_test` 真写 2.4MB 验证:3 个文件、单文件
<1.1MB、总计 ≤3MB。

### ✅ P0-3 一个目标出异常拖垮整批(已完成)

`hide_pids` per-pid `try/except`,异常写日志并计入失败,继续处理下一个。

### ⬜ P0-4 免 Python 的发行版(未做,发布最大短板)

`tools/build_exe.py` + PyInstaller `--onefile --windowed`,manifest 用
`asInvoker`(故意不默认要求管理员)。验收:没装 Python 的机器双击能跑。

### ⬜ P0-5 管理员权限目标的真机闭环(需要人配合)

见 [`MANUAL_TESTS.md`](MANUAL_TESTS.md) A 组。代码侧已做权限预检 + 回滚。

## P1 · 从"能用"到"好用"

### ✅ P1-1 场景(profile)

配置升到 v2,`profiles[]` + `active_profile`。切换语义三条:
藏本场景命中的 → 放掉**别的场景**藏的 → 手动藏的不动。场景可带 `mute`。
v1 自动迁移并备份成 `config.v1.bak.json`。托盘 + 主界面都有场景入口。

### ✅ P1-2 规则持续生效

设置里「规则持续生效」(默认关)。开着的每 3 秒按当前场景匹配一次新窗口,
命中就藏。**用户手动点过恢复的进程不会被抢回去**(`opt_out`,进程退出才清)。

### ✅ P1-3 关键进程保护名单

`core/protect.py` 内置 14 个系统/输入关键进程(dwm / 输入法 / UWP 宿主等),
设置里可加自定义。列表里标「受保护」、拒绝隐藏并说明原因,不是静默跳过。

### ✅ P1-4 托盘菜单重排

切换 → 场景(子菜单) → 显示主界面 → 最小化到托盘 → 以管理员重启 → 退出。

## 明确不做

- **注入 DLL / 全局钩子 / 模拟键鼠去操控目标程序** —— 那是外挂的路子,会被
  反作弊盯上,也让"只动窗口状态"这个清白前提失效。
- 移动端 / 云端同步 / 账号体系。
- "让隐藏更彻底"的驱动级方案(内核过滤、隐藏进程)—— 上一个 driver 就意味着
  数字签名、蓝屏风险、杀软误报,收益完全不值。
