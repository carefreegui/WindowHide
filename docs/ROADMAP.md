# 后续优化路线

> 排序依据只有两条:**会不会让人以为工具坏了**、**能不能被别人用起来**。
> 每条都写清"改哪里 / 为什么 / 怎么验收",不写工期。

## P0 · 先修"会让人以为工具坏了"的

### P0-1 无响应窗口让界面周期性卡顿

**现象**:实测 3 个挂起窗口 → refresh 从 31ms 变成 349ms;每 1.5s 触发一次,
每次卡在主线程上。10 个挂起窗口就超过 1 秒,用户感觉是"点了隐藏没反应"。

**为什么**:`get_window_text` 用 `SendMessageTimeoutW(SMTO_ABORTIFHUNG, 100ms)`
防止无限阻塞 —— 但**每个挂起窗口都要等满 100ms**,而且是每轮都重新等。

**改哪里**:
- `win32.get_window_text()` 增加"超时"返回值(或单独 `is_hung(hwnd)`)
- `main_window` 维护 `_hung: dict[hwnd, 复活时间]`,命中就跳过取标题和图标,
  30 秒后再试一次
- 表格里这类窗口标题显示 `(无响应)`,而不是空白(用户要能看懂)

**验收**:起 3 个 `tests/hang_probe.py`,refresh < 50ms/次;
`hang_test.py` 扩展断言"同一挂起窗口第二轮不再等待"。

### P0-2 日志无限增长

**现象**:`%APPDATA%\WindowHide\windowhide.log` 追加写,永不清理。长期挂机
会变成几十 MB。

**改哪里**:`log.py` 加 1 MB 轮转,保留 3 份(`.log` / `.log.1` / `.log.2`)。

**验收**:循环写入 > 2 MB 后检查文件被轮转、总大小有界。

### P0-3 一个目标出异常会拖垮整批隐藏

**现象**:`hide_pids` 里对每个 pid 直接调 `_hide_one`,中间抛异常(比如窗口
在枚举途中销毁)会让整个循环中断,剩下勾选的窗口一个都不藏。

**改哪里**:per-pid `try/except`,异常写日志 + 计入 `failed`,继续处理下一个。

**验收**:注入一个会抛异常的桩,断言其余 pid 仍然被隐藏。

### P0-4 没有免 Python 的发行版(发布最大短板)

**现象**:目标用户是普通 Windows 用户,不会 `python -m venv`。

**改哪里**:
- `tools/build_exe.py`:`PyInstaller --onefile --windowed --name WindowHide run.pyw`
- 配套 `WindowHide.spec` 里挂 manifest:`requestedExecutionLevel level="asInvoker"`
  (**故意不用 requireAdministrator** —— 默认提权会让"隐藏普通程序"也弹 UAC,
  用户会烦;管理员场景走托盘里的「以管理员身份重启」)
- GitHub Release 附 zip,README 加"不想装 Python 就下 Release"

**验收**:在**没装 Python** 的机器/账户上双击 exe 能起来、能藏窗口;
托盘「以管理员身份重启」从 exe 启动也能正常交接单实例。

### P0-5 管理员权限目标的真机闭环(需要人配合)

见 [`MANUAL_TESTS.md`](MANUAL_TESTS.md) A 组。代码侧已做权限预检 + 回滚,
但"到底能不能藏住永劫无间"只有真机能验。

## P1 · 从"能用"到"好用"

### P1-1 场景(profile):一份配置管一组动作

**现状**:`targets` 是一个平铺的规则列表,勾什么藏什么。想切"上班 / 摸鱼 /
游戏"就得重新勾一遍。

**改成**:配置文件升到 v2
```jsonc
{
  "version": 2,
  "profiles": [
    {"name": "上班", "hide": ["Steam.exe", "WeChat.exe"], "mute": true},
    {"name": "游戏", "hide": ["WeChat.exe"], "mute": false}
  ],
  "active_profile": "上班"
}
```
- 托盘菜单直接挂场景列表(不进主界面就能切)
- `v1 → v2` 迁移:`targets` 自动包成 `{"name": "默认", "hide": [...}`
- 迁移失败必须**保留原文件备份**再写新格式

**验收**:v1 配置文件启动后被正确升级,原规则一条不丢;`logic_test` 覆盖迁移。

### P1-2 规则持续生效(进程重启后自动再藏)

**现状**:规则只在"启动时匹配",目标程序重启后新 pid 不会自动再藏 ——
规则从"生效"退化成"记住"。

**改成**:`HideController` 里加一个低频轮询(3 秒),只做一件事:
拿已保存规则的进程名去比对**当前新出现的窗口**,命中就自动隐藏。
不做全量枚举的重复工作,复用 `refresh` 的结果。

**风险**:用户可能不希望"一开就藏"。默认关闭,设置里叫「规则持续生效」。

**验收**:藏掉记事本 → 关闭记事本 → 重新打开 → 3 秒内自动被藏。

### P1-3 关键进程保护名单

**现状**:只有桌面/任务栏(`is_shell_window`)被拦。用户仍然可以勾选
`explorer.exe` 的其它窗口、`csrss` 之类。

**改成**:内置不可隐藏名单(`explorer.exe` / `winlogon.exe` / `dwm.exe` /
`TextInputHost.exe` …)+ 设置里可加自定义"永不隐藏"。

**验收**:勾选 explorer 的窗口点隐藏 → 弹提示"这是系统外壳,已跳过"。

### P1-4 托盘菜单重排

场景上线后,托盘菜单会变长。按"最常用在上"重排:切换 → 场景 → 显示主界面 →
以管理员重启 → 退出;场景用子菜单。

## P2 · 工程与体验

| 项 | 说明 |
| --- | --- |
| 音频渐变 | 现在只有静音 on/off。改成 0.2 秒内把音量淡到 0,恢复时淡回原值。好处:不会在系统音量合成器里留下"已静音"的持久状态 |
| 独占模式音频 | 游戏用 WASAPI 独占时拿不到会话,现在静不了音也不报错。改成"检测到目标有音频会话但静音无效"时提示 |
| 拆 `win32.py` | 802 行拆成 `win/window.py`(枚举/样式)、`win/process.py`(进程树/完整性)、`win/monitor.py`(显示器/全屏判定),纯搬运不改行为 |
| i18n | UI 文案全硬编码中文。抽出 `ui/strings.py` + `README.en.md`,至少让英文用户看得懂截图 |
| 多显示器全屏判定 | 现在按"窗口所在那一块显示器"判断,横跨多屏的全屏窗口会漏判 |
| 状态文件版本统一 | `hidden_state.json` 只有 v1 没有迁移框架,和 P1-1 一起做 |

## 明确不做

- **注入 DLL / 全局钩子 / 模拟键鼠去操控目标程序** —— 那是外挂的路子,会被
  反作弊盯上,也让"只动窗口状态"这个清白前提失效。
- 移动端 / 云端同步 / 账号体系。
- "让隐藏更彻底"的驱动级方案(内核过滤、隐藏进程)—— 上一个 driver 就意味着
  数字签名、蓝屏风险、杀软误报,收益完全不值。
